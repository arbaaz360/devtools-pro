## Branch

`claude/AG-109-jwt-decoder` from the latest `origin/main`. Record the base SHA.

## Allowed files

```text
plugins/jwt/**
```

## Required reading

`ARCHITECTURE.md`, `Tool Contract and Document Model.md`,
`packages/plugin-sdk/README.md`, the DU-04 card in
`docs/DEVUTILS_REQUIREMENTS.md`, the "working" rules in
`docs/WORKER_PROTOCOL.md` (a processor uses web platform APIs only), and two

## Goal

A new package `plugins/jwt/` with plugin id `security.jwt` that decodes a JSON
Web Token into its header, payload and signature, verifies the signature
offline for the HS, RS, PS and ES families with a caller-supplied key, and
reports claim validity (expiry, not-before) separately from signature validity.

## Requirements

- Package files as in the reference packages; `tests.requirementIds: ["DU-04"]`.
- One tool `security.jwt`, category `security`, one operation `security.jwt`.
  Input port `input`, kind `document`, text: one token, surrounding whitespace
  ignored. Output port `output`, kind `value`, representations
  `["properties", "text"]`.
- Options (kebab-case ids, camelCase aliases accepted, unknown keys and wrong
  types are structured errors naming the option):
  - `key` string, default `""`, `sensitive: true`. The HMAC secret for HS*, or
    a PEM public key (`-----BEGIN PUBLIC KEY-----`, SPKI) for RS*, PS*, ES*.
    Empty means "decode only, do not verify".
  - `secret-encoding` enum `utf8`, `base64`, `base64url` (default `utf8`), how
    `key` is read for HS*.
  - `clock-tolerance-seconds` integer ≥ 0, default `0`, applied to `exp` and
    `nbf`.
- Decoding, stated in the README: three base64url segments separated by `.`;
  padding optional; header and payload must be JSON objects; the third segment
  may be empty only when `alg` is `none`. Anything else is a structured error
  naming the segment (`header`, `payload`, `signature`) and the reason.
- Verification with WebCrypto (`crypto.subtle`) only: HS256/384/512 via HMAC;
  RS256/384/512 via RSASSA-PKCS1-v1_5; PS256/384/512 via RSA-PSS with salt
  length equal to the hash length; ES256/384/512 via ECDSA over P-256/P-384/
  P-521 with the JOSE raw `r||s` signature. `alg: none` never verifies: report
  `signature: "none"`. An `alg` outside this list is `signature: "unsupported"`
  with the value named, not an exception. A key that does not import for the
  algorithm family is a structured error naming the family.
- Result value:
  `header` (object), `payload` (object), `algorithm`, `signature` one of
  `valid`, `invalid`, `not-checked` (no key), `none`, `unsupported`;
  `claims`: `{ expired, notYetValid, expiresAt, notBefore, issuedAt }` with ISO
  UTC strings computed against `context.clock.now()`, `null` when the claim is
  absent; `valid`: `signature === "valid"` and neither `expired` nor
  `notYetValid`. The text representation is the header JSON, a blank line, the
  payload JSON, a blank line, then `signature: <status>` and one `claim: value`
  line per present claim, all with two-space indentation so each block is
  copyable.
- Secrets never appear in output, errors, or diagnostics: the `key` option
  value is not echoed anywhere, including in "invalid key" messages.
- Limits: `maxInputBytes` 64 KiB, `maxOutputBytes` 1 MiB. Cancellation polled
  before and after the WebCrypto call. Source bytes immutable, asserted per
  test.
- Fixtures under `fixtures/`: generated by `test.mjs` itself with
  WebCrypto (`crypto.subtle.generateKey` for RSA and EC, a fixed HMAC secret),
  so no key material is committed except the fixed HMAC secret and one static
  RS256 token with its public key from RFC 7515 Appendix A.2. Cover: every
  algorithm family valid and with the wrong key; `alg: none` with and without a
  signature segment; malformed base64; header that is not an object; payload
  that is not JSON; `exp` in the past with and without tolerance; `nbf` in the
  future; `exp` expired but signature valid (must report `expired: true`,
  `signature: "valid"`, `valid: false`); unsupported `alg: "HS1"`; a key for the
  wrong family; empty key (`not-checked`).
