# AG-139 — X.509 certificate decoder (new package)

## Branch

`antigravity/AG-139-x509` from the latest `origin/main`. Record the base SHA.

## Allowed files

```text

```

## Required reading

`ARCHITECTURE.md`; `packages/plugin-sdk/README.md`; `docs/WORKER_PROTOCOL.md`,
including "Where an expected value comes from"; `plugins/jwt/`, the reference: a
`security` tool that reads PEM and uses WebCrypto; and RFC 5280 §4.1 and §4.2.1.

## Goal

A new package `plugins/x509/`, plugin id `security.x509`, that decodes X.509
certificates and shows what is in them. It is in the target catalogue ("certificate
decoding", `docs/PARITY_AND_BUILDING_BLOCKS.md`) and not yet built.

## Requirements

- **Package files as in the reference.** `tests.requirementIds: []`.
- **The tool:** one tool `security.x509`, title `Certificate Decoder`, category
  `security`, and one operation `security.x509`.
  - Input port `input`, a text document.
  - Output `output`, representations `["text", "properties"]`.
  - Triggers `explicit` + `inputChange`.
  - Limits: 1 MiB in, `deadlineMs` 1000.
- **Input:** one or more PEM certificates (`-----BEGIN CERTIFICATE-----`), text around
  them ignored; or a single Base64 DER certificate with no PEM armour.
- **Parsing** uses **only web platform APIs**; no `node:` imports, since the processor
  runs in the desktop webview.
  - Write a small DER reader: tags, **definite lengths only**, OIDs, INTEGER, BIT
    STRING, OCTET STRING, the string types, UTCTime and GeneralizedTime.
  - Refuse BER indefinite lengths and nesting deeper than 64, as structured errors
    (`x509.not-der`, `x509.too-deep`). Never crash, and never loop forever on
    malformed input.
- **Per certificate, the text report and a properties entry give:**
  - `version`;
  - `serialNumber`: uppercase hex, no separators, the unsigned magnitude as
    `openssl x509 -serial` prints it;
  - `subject` and `issuer`: RFC 4514 strings, as
    `openssl x509 -nameopt RFC2253,utf8 -subject` prints them;
  - `notBefore` and `notAfter`: ISO 8601 UTC. A UTCTime two-digit year follows RFC
    5280 §4.1.2.5.1: YY ≥ 50 → 19YY, YY < 50 → 20YY;
  - `expired` and `notYetValid`, against `context.clock.now()`;
  - `sha1Fingerprint` and `sha256Fingerprint`: uppercase colon-separated hex of the
    DER, from `crypto.subtle.digest`;
  - `publicKey`: `{ algorithm, bits }` for RSA, `{ algorithm, curve }` for EC (P-256,
    P-384, P-521), and `Ed25519`;
  - `signatureAlgorithm`, by name (`sha256WithRSAEncryption`, `ecdsa-with-SHA256`,
    `ED25519`, …), else the dotted OID;
  - `subjectAltName`: DNS, IP (IPv4 dotted, IPv6 in RFC 5952 form), email and URI;
  - `keyUsage`: RFC 5280 names;
  - `extendedKeyUsage`: names for serverAuth, clientAuth, codeSigning,
    emailProtection, timeStamping and OCSPSigning, else the dotted OID;
  - `basicConstraints`: `{ ca, pathLen }`;
  - `isSelfSigned`: subject equals issuer, bytewise on the DER names.
- **Properties** also give `certificates` (the count) and `bytes`.
- `README.md`: the fields, the accepted input, the refusals, and that nothing is
  validated (no chain or revocation checks).

## Evidence

**The certificates are made by OpenSSL, and the expected values come from
`node:crypto` and OpenSSL, not from this package.**

- **Make the fixtures.** Commit `plugins/x509/fixtures/make-certs.sh`, run with Git's
  `openssl` (`/mingw64/bin/openssl`, 3.2 on this machine). It generates:
  - RSA 2048 and 4096; EC P-256, P-384 and P-521; Ed25519;
  - a subjectAltName with DNS, IPv4, IPv6, email and URI entries;
  - a CA with `pathlen:1` and `keyCertSign`, and a leaf with serverAuth and
    clientAuth EKUs;
  - a certificate valid past 2050 (a GeneralizedTime `notAfter`);
  - a serial whose first byte is ≥ 0x80 (DER adds a leading zero);
  - a UTF-8 subject (`CN=Zoë ☃`);
  - a three-certificate PEM chain.

  Commit the certificates only. Delete the private keys in the script, and make sure
  none is staged.
- **Check against `node:crypto` at test time.** `test.mjs` compares each certificate's
  output with `new crypto.X509Certificate(pem)`: `serialNumber`, `validFrom`/`validTo`
  (compared as instants), `fingerprint` and `fingerprint256`, `subjectAltName`,
  `keyUsage`, `ca`, and the public key's `asymmetricKeyType` and
  `asymmetricKeyDetails` (`modulusLength`, `namedCurve`). Node is the oracle only in
  the test; the processor never imports it.
- **Check the RFC 4514 names against OpenSSL.** `make-certs.sh` also writes
  `openssl x509 -noout -subject -issuer -nameopt RFC2253,utf8` for each certificate
  to a committed `.names` file, which the test compares with.
- **Also cover:** input with text around the PEM; bare Base64 DER; a truncated
  certificate; a BER indefinite length; random bytes. Each must be a structured error,
  never a crash.
