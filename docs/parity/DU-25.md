# DU-25 — Markdown Preview (`preview.documents`, operation `preview.markdown`)

`preview.markdown` renders Markdown with the vendored `marked` (GFM tables,
task lists, strikethrough, autolinks; `breaks` and a `light`/`dark` `theme`
as options) and always wraps the result in the same self-contained document
shell `preview.html` uses, complete with its inline reset/typography CSS.
Raw HTML in the source and script-tag counts are reported, not sanitized or
removed, matching the package's documented "the shell's sandbox is the
safety boundary" design. The one output artifact carries three
representations (`previewDocument`, `code`, `properties`), which covers
"rendered preview" and one HTML(+CSS) source view, but not two textually
distinct source views (a bare fragment vs. the wrapped document) as the
card's three-way "rendered / HTML source / HTML+CSS source" split implies.

No `partial`/`missing` row needs more detail than already given, except:
row 2 — a true "HTML source without CSS" view would require the processor
to expose the unwrapped fragment as a second representation alongside the
current full document, which does not exist today.

## Not covered

The Markdown editor, view-mode selector, clipboard/sample/clear buttons,
the "Open in Browser" OS integration, and any syntax highlighting of the
Markdown source itself are shell/presentation concerns outside a headless
audit. Whether the rendered preview frame is actually sandboxed with
scripts/navigation/network disabled at runtime (as opposed to declared in
the manifest) was not observed running.
