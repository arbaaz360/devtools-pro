# DU-07 — Query String Parser / URL Parser

`web.url-parser` (operation `url.parse-query` in the `web.url` package) parses a bare query, a `?`-prefixed query, a `scheme://host/path?query#fragment` reference, or a full absolute URL into a JSON `parameters` object plus an ordered `entries[]` list, with array (`name[]`) support, exact byte-offset error reporting, and documented, fixture-backed bracket/nesting semantics. This is the most complete of the seven cards audited in this packet: every Required, UX and Acceptance item checked has a concrete, headlessly-verifiable answer, and the one place the card asks the implementation not to overclaim (a full URL-components editor) is honestly not claimed.

## Gaps to close

None found for this card within processor scope — every Required/Acceptance item maps to a `met` row. The only rows not `met` are legitimately `n/a (shell)` (presentation, detection thresholds, an editor UI the card explicitly says not to assume).

## Not covered

- Paste/sample/clear buttons, JSON syntax highlighting rendering, and the detection/reset preference control are shell UI, not observable headlessly.
- Whether a future URL-components editor (beyond the read-only `components` field) is planned or tracked elsewhere — out of scope for this audit.
- `text.url` (percent encode/decode, DU-05) shares this package but is a different card; not audited here beyond confirming it is a separately titled/aliased tool from `web.url-parser`.
