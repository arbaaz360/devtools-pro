# DU-17 — YAML to JSON (`convert.yaml`, operation `convert.yaml-json`)

`convert.yaml-json` is a hand-written, dependency-free YAML 1.2 core-schema
parser that converts a single YAML document to JSON with a 2-space,
4-space or minified indent, plus a recursive key-sort option. It supports
the full documented subset — block and flow collections, all three scalar
quoting styles, both block-scalar styles with every chomping mode, comments
— and, per its own stated policy, rejects rather than silently mishandles
everything it doesn't support: anchors, aliases, tags, directives, multiple
documents, duplicate keys, tab indentation and trailing commas each get
their own named error code and a byte/line/column position. Every
requirement in this card is met; the two "reject entirely" choices (aliases,
custom tags) are exactly the policy the card itself calls for ("limit alias
expansion and reject unsupported custom tags rather than constructing
arbitrary objects"), not a shortfall.

| # | What the card requires | What the tool does | Verdict | Evidence |
|---|---|---|---|---|
| 1 | Valid YAML document to JSON | Parses the documented subset and emits an `application/json` artifact | met | `--operation convert.yaml-json --input 'input=a: 1'` → `{"a":1}` |
| 2 | 2-space indented output | `indent: "space2"` (default) | met | scratchpad run, `a:\n  b: 1` → `{\n  "a": {\n    "b": 1\n  }\n}\n` |
| 3 | Minified output | `indent: "minified"` | met | `--options '{"indent":"minified"}' --input 'input=a:\n  b: 1\n  c: [1,2,3]'` → `{"a":{"b":1,"c":[1,2,3]}}` |
| 4 | 4-space indented output (bonus beyond the card's two named modes) | `indent: "space4"` | met | scratchpad run, `a:\n  b: 1` with `indent: space4` → `{\n    "a": {\n        "b": 1\n    }\n}\n` — correctly 4 spaces, unlike the sibling SQL package's equivalent option (see `DU-26.md` row 9) |
| 5 | Highlighted JSON output | Output declares `language: "json"` for the shell's editor/highlighter; actual syntax highlighting is rendered by the shell | n/a (shell) | `manifest.json` operation `outputs[0].language` = `"json"` |
| 6 | UX: YAML source language / JSON result language, Clipboard/Sample/Clear/Copy | Input/output ports and export capabilities are declared; the editors and buttons are shell components | n/a (shell) | `manifest.json` `inputs[0]`, `outputs[0].exports` |
| 7 | Switching result formatting preserves the source | Each operation call is a pure function of the immutable source bytes plus `options`; `indent`/`sort-keys` never touch the source | met | source-immutability is asserted by every test in `plugins/yaml/test.mjs` (100/100 pass) |
| 8 | Nested collections | Block and flow mappings/sequences nest arbitrarily, including mixed forms | met | `fixtures/valid/*.yaml` (54 pairs) cover nested collections; `--input 'input=a:\n  b: 1\n  c: [1,2,3]'` → `{"a":{"b":1,"c":[1,2,3]}}` |
| 9 | Quoted scalar types | Plain, single- and double-quoted scalars, including JSON-style and `\x`/`\U`/`\0` escapes | met | README §"YAML subset"; exercised by the fixture suite (`plugins/yaml/test.mjs`) |
| 10 | Aliases | `&anchor`/`*alias` are rejected outright with `yaml.anchor-unsupported`/`yaml.alias-unsupported`, matching the card's own stated policy of limiting alias expansion rather than expanding it | met | scratchpad/headless run: `input=a: &anchor 1\nb: *anchor` → `YamlError: yaml.anchor-unsupported: anchors (&) are not supported` before any object is constructed |
| 11 | Numeric precision | Integers beyond `Number.MAX_SAFE_INTEGER` are emitted as a JSON string of their exact digits (with an `info` diagnostic) instead of being rounded through `Number` | met | `--input 'input=big: 18446744073709551615'` → `{"big":"18446744073709551615"}`, `diagnosticsDetail: [{"code":"yaml.unsafe-integer", ...}]` |
| 12 | Non-JSON YAML values (`.inf`, `.nan`) | Converted to JSON `null` with an `info` diagnostic (`yaml.float-special`), since JSON has no such value | met | `--input 'input=x: .inf\ny: .nan'` → `{"x":null,"y":null}`, two `yaml.float-special` diagnostics |
| 13 | Duplicate keys | Hard rejection (`yaml.duplicate-key`), not last-write-wins or silent merge — a deliberate, YAML-specific policy the README explains (`plugins/json` instead keeps both and warns) | met | `--input 'input=a: 1\na: 2'` → `YamlError: yaml.duplicate-key: duplicate mapping key "a"` |
| 14 | Multiple documents | Rejected outright (`yaml.multiple-documents`) rather than silently parsing only the first or merging | met | `--input 'input=a: 1\n---\nb: 2'` → `YamlError: yaml.multiple-documents: input contains more than one YAML document` |
| 15 | Declare YAML schema/version and conversion policy | README explicitly states YAML 1.2 core schema and documents every typing/rejection rule | met | `plugins/yaml/README.md` §"YAML subset", §"Scalar typing" |
| 16 | Limit alias expansion and reject unsupported custom tags rather than constructing arbitrary objects | Aliases are unsupported outright (limit = zero, the strictest possible limit); `!tag` is rejected with `yaml.tag-unsupported` before any value is built | met | rows 10 above; `!tag` rejection documented in README §"Rejected" |
| 17 | `sort-keys` option (bonus, not explicitly named by the card) | Recursively sorts every mapping's keys when `true` | met | `--options '{"sort-keys":true}' --input 'input=b: 2\na: 1'` → `{"a":1,"b":2}`, `diagnostics:0` |

## Not covered

The editor language identifiers actually shown to the user, the Clipboard/
Sample/Clear/Copy buttons, and whether the shell's JSON syntax highlighter
is wired to this output — all shell/presentation concerns per the packet's
scope. Also not exercised here: the documented known limitations already
disclosed in `plugins/yaml/README.md` (embedded literal `\r` inside a
round-tripped block scalar; compact one-line nested sequences like `- - a`),
since the card does not name these as acceptance scenarios and the package
already states them as intentional limitations rather than defects.
