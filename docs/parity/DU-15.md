# DU-15 JavaScript Beautifier/Minifier

The `format.js` plugin integrates `js-beautify` for formatting and uses a custom tokenizer for minification. It generally fulfills the card's processing requirements, but since it lacks a full AST parser, it cannot report structural parse problems.

| # | What the card requires | What the tool does | Verdict | Evidence |
|---|---|---|---|---|
| 1 | 2/4 spaces, one tab | Supports `space-2`, `space-4`, `tab` options | met | `--options '{"indent":"space-4"}'` → `"options":{"indent":"space-4"}` (implicitly via `js-beautify`) |
| 2 | minify | Provides a `minify` operation | met | `--operation minify` → `"executed":"format.js/minify"` |
| 3 | incomplete JavaScript | Formats incomplete fragments via `js-beautify` | met | `--operation beautify --input "input=function ("` → `"bytes":10` |
| 4 | syntax highlighting | Relies on the shell for presentation | n/a (shell) | N/A |
| 5 | indicate recoverable parse problems during incomplete edits | Indicates lexical errors (unterminated strings/comments) but not structural parse errors (missing braces) | partial | `--input "input=function ("` → `"diagnostics":0` |
| 6 | Processor runs off the UI thread | JS worker executor configured in manifest | met | Manifest `"executor": { "kind": "javascriptWorker" }` |
| 7 | modern supported syntax with explicit version | Relies on `js-beautify` 2.0.3 (vendored) | met | `packages/vendor/js-beautify` version in `package.json` |
| 8 | comments, regex literals, template literals | Tokenizer handles all these natively | met | README describes tokenizer rules for all three |
| 9 | automatic-semicolon edge cases and incomplete fragments | Implements ASI heuristic newline preservation | met | README section "ASI (Automatic Semicolon Insertion) Newline Rule" |
| 10 | No input execution; no claim of lossless minification unless semantic fixtures pass | Explicitly declares limits of the AST-less minifier | met | README: "For heavily ASI-dependent code, a full parser-based minifier should be used" |

Closing gaps:
- To fully meet "indicate recoverable parse problems", the plugin would need to adopt an actual AST parser (like Acorn or Babel) capable of reporting structural syntax errors, rather than relying solely on a lexical tokenizer.

## Not covered

Presentation-specific requirements (editable source, formatting UI) are not verified headlessly.
