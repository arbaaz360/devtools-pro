# DU-24 — HTML/SVG to JSX (`convert.jsx`)

`convert.jsx` parses an HTML or SVG fragment with a tolerant, recovering
tokenizer and emits formatted JSX: attribute renaming (`class`→`className`,
`for`→`htmlFor`, event handlers, and the rest of the standard React
attribute map), inline `style` strings turned into style objects, SVG
attribute camelCasing (with `viewBox` correctly left alone), boolean
attributes, self-closing void elements, HTML comments converted to JSX
block comments with `*/` escaped, and safe `{`/`}` escaping in text nodes.
Malformed input (stray end tags, unclosed elements) produces a best-effort
tree plus structured warning diagnostics instead of failing outright. Every
stated requirement is met; this is the strongest of the six packages
audited in this packet.

| 4 | Preserve source semantics while mapping JSX-specific attributes | `class`, `for`, `tabindex`, `readonly`, `colspan`, `onclick`, etc. rename without changing the value | met | scratchpad run: `<div class="a" for="x" tabindex="1" readonly colspan="2" onclick="foo()">` → `<div className="a" htmlFor="x" tabIndex="1" readOnly colSpan="2" onClick="foo()">`, `"attributesRenamed":6` |

## Not covered

The source/result editor panes, Sample/Clipboard/Clear/Copy buttons, and
language-aware code folding are shell/presentation features outside a
headless audit. This audit did not attempt to actually execute the emitted
JSX through a JSX transform/React renderer to confirm it is syntactically
valid in every case; it checked the emitted text against the card's stated
transformation rules directly.
