# DU-21 — QR Code Reader/Generator (`media.qr`)

`media.qr` today is a generator only: one operation turns plain UTF-8 text
into a QR code SVG, with error-correction level, cell size, margin and
version as options. It has no reading capability at all (no image input
port, no decode operation — that is `AG-123`, still open), no content-type
templates (URL/phone/SMS/email/vCard/event/Wi-Fi are just raw text the user
would have to hand-type in the correct syntax themselves, since neither the
processor nor the workspace's form options offer template composition), and
no watermark/logo/icon support. Worse, this audit found that the generator
does not actually encode Unicode text correctly: it uses the vendored
`qrcode-generator` library's default `stringToBytes`, which takes each
UTF-16 code unit modulo 256 rather than the character's real UTF-8 bytes,
so any input containing a non-ASCII character produces a QR code that an
independent decoder (the repository's own vendored `jsQR`) cannot read back
correctly — this was verified directly, not inferred, using the exact SVG
bytes the processor writes.

## Not covered

Everything about the reader side of this card (file/clipboard image input,
malformed-image handling, decode UI) is out of scope for this package as it
stands today; it belongs to `AG-123`, tracked separately. The top-aligned
image result layout, file/clipboard actions and the settings form itself
are shell/presentation concerns. This audit's Unicode finding (row 12) was
verified by independently decoding the processor's actual SVG output
through the repository's vendored `jsQR`, not by reading the encoder source
alone — no code was changed to do this, per the packet's scope.
