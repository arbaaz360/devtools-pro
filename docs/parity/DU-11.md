# DU-11 — HTML Preview (`preview.documents`, operation `preview.html`)

`preview.html` renders a rendered document in a sandboxed frame: it either
passes a full HTML document through byte-for-byte (detected by a leading
`<!DOCTYPE`/`<html`, skipping whitespace and complete comments first) or
wraps a fragment in the package's own minimal document shell. Scripts are
never executed anywhere in this design — the safety story is entirely "the
shell's iframe sandbox has no script/navigation/network capability," full
stop. That satisfies the card's baseline safety acceptance criteria, but it
also means the three settings the card explicitly asks for — independently
toggleable JavaScript, navigation, and outgoing-resource loading, each
defaulting to disabled — do not exist: there is no option, anywhere in the
manifest or the processor, to turn any of them *on*. Reload/reset and
inspect-element behavior are pure shell concerns this audit cannot reach.

## Not covered

The rendered preview pane, reload/reset buttons, clipboard/sample/clear
actions, and any inspect-element integration are shell/webview features
this audit cannot reach headlessly. Whether the shell's actual `<iframe>`
sandbox attributes correctly block navigation/network/scripts today (as
opposed to the processor never offering a way to turn them on) is also a
shell-level fact this audit did not observe running.
