# DU-06 — Base64 String Encoder/Decoder

`encoding.base64-text` encodes the exact bytes of a document as Base64 and decodes Base64 back to bytes, labelling the decoded result as text or binary, with explicit, independently-selectable policies for alphabet (`standard`/`url`), padding, and whitespace/canonical-form strictness, and twenty distinct structured diagnostics with byte-offset/line/column positions. It matches nearly all of the card's Required and Acceptance list in detail — the one clear gap is that the output port has no `useAsInput` export, so the card's "Use as input" UX action has nothing to bind to.

## Gaps to close

- **Row 11 (missing): no `useAsInput` export.** The card's UX list names "Use as input" alongside Copy for this tool, the same as URL Parser and RegExp Tester already have. Closing it is a one-line manifest change (`"exports":["copyText","save","useAsInput"]`) plus whatever the shell needs to route a `value` output back into a `document` input — worth checking whether other `value`-kind outputs in the catalog already do this before assuming it is trivial.

## Not covered

- Presentation: Encode/Decode selector rendering, input/output layout, Clipboard/Clear buttons, and detection disable/reset are shell UI, not observable headlessly.
- Whether a binary result is actually offered to another tool/export target in the running app (no such routing exists in the processor to observe).
- Whether the desktop shell has a separate image-Base64 tool elsewhere in the codebase (native tools are out of scope for this audit per the packet).
